# Методология тестирования

## 1. GoTestWAF (Бенчмаркинг)
Основной инструмент для замера эффективности WAF. Запуск производился с JWT-токеном авторизации для доступа к защищенным эндпоинтам.

**Используемые статус-коды при тестировании:**
*   `--blockStatusCodes=403,413,400`: Код 403 (блокировка WAF), 413 (Payload Too Large - Apache отбил 128kb пейлоад), 400 (Bad Request - сбой парсинга Multipart).
*   `--passStatusCodes=200,500`: Код 200 (атака прошла), 500 (ошибка приложения, WAF пропустил).

**Pre-flight проверка:** Перед каждым запуском валидировался JWT-токен через `curl https://juice.local/rest/user/whoami` во избежание получения ложных `401 Unauthorized` вместо реальных `200 OK`.

## 2. WAF-Bypass (Фаззинг)
Инструмент использовался для проверки устойчивости к обфускации. Из 6829 пейлоадов WAF успешно заблокировал 69%, ложных срабатываний — 0.09%. Оставшиеся 30% (Bypassed) — это результат применения сложных мутаций (двойное кодирование, разрыв токенов комментариями), что является нормальным показателем для WAF без эвристического анализа на базе ML.

## 3. Inoue & OWASP ZAP (Реконнесанс)
*   **Inoue** использовался для фингерпринтинга технологического стека и проверки заголовков безопасности (Security Headers).
*   **ZAP** применялся для автоматического сбора эндпоинтов (AJAX Spider) и проверки бизнес-логики.
